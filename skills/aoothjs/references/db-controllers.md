# db-controllers

`AsArbacDbController` and `AsArbacDbReadableController` — Moost-DB controllers that enforce per-row scope on reads, writes, removes, and `/meta`. **No tables or migrations live here** — the package does not own role/privilege storage.

## `AsArbacDbController<T>` / `AsArbacDbReadableController<T>`

`AsArbacDbController<T>` extends `AsDbController<T>` from `@atscript/moost-db`. Adds ARBAC enforcement via the six protected seams on `AsDbController`. Use for tables with both read and write access. `AsArbacDbReadableController<T>` extends `AsDbReadableController<T>` — view-only counterpart, only read-side seams.

Both classes work over `@db.view` models too (bind with `@ReadableController(ViewModel)`): every read-side seam goes through the bound READABLE surface, never the writable `.table` getter (which throws for view-bound controllers by moost-db design). Prefer `AsArbacDbReadableController` for pure dict/value-help views; the writable class over a view is also safe for reads — its write routes fail loudly at moost-db's `.table` guard, which is the intended contract.

Both controllers resolve scopes ONCE per request in `prepareRequest` (first hook on every endpoint, `@DbAction`s included — `endpoint: "action"`, moost-db ≥ 0.1.143): reuse the interceptor's cache, else evaluate — deny → **403** on every route; a missing interceptor and `@Public()` do NOT open the table (0.1.72+). Every other hook reads the resolved scopes synchronously; unresolved → 403 (never unrestricted).

**Empty-scope rule** (0.1.72+, `normalizeScopes` from `@aooth/arbac`): allowed without a `scopes` list → unrestricted `[{}]`; a `scope` fn returning `undefined` → that rule contributes nothing; allowed with no scope left (`scopes: []`) → **403**. Every deny answers `Insufficient privileges for action "<a>" on resource "<r>"`.

## Protected hook table

| Hook                                        | When                                       | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `transformFilter(filter)`                   | Every read query                           | Merges user filter with union of scope filters via `conjoinScopeFilters` → `$and: [merged, userFilter]` — **never object spread**, which would let a user filter on the same field replace the scope's and widen access. On deny returns a match-nothing filter (`{ $or: [] }`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `transformProjection(projection)`           | Every read query                           | Unions per-scope `projection` whitelists and narrows the user `$select` to the INTERSECTION with that union — array (inclusion) and object (exclusion) forms both; a requested parent whose descendants the scope constrains is split by schema (`$select=a` under `{ "a.b": 1 }` or `{ "a.c": 0 }` → only `a.b`); excluded nested objects are stripped by their leaves. Same rule inside `$with` sub-selects. Empty union → unrestricted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `validateControls(controls, ...)`           | Every read with `controls.*`               | Runs the parent validator first; then invokes `enforceControlsPolicy(unionControlsPolicy(scopes), controls)`. Violations throw `HttpError(403, 'Control "$with" is not allowed for your role')`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `applyMetaOverlay(meta)`                    | `/meta` requests                           | Evaluates ARBAC in parallel for every declared action and CRUD op; filters `meta.actions` and `meta.crud`, then PRUNES the field surface (`fields`, serialized `type`, `relations`, `versionColumn`) by the union of the allowed read ops' scope projections — a scoped UI cannot even offer hidden columns. PK + `preferredId` always survive; unscoped read grant → full envelope; NO read op allowed → field surface untouched (write-only forms need `type`). Relations + nav types follow the `$with` policy (declared `with.<rel>` sub-scope, else the caller's own grant on the related table; none → dropped), matching `hasField`; `ref`s to hidden fields / unreadable tables stripped; derived fields follow their source; SQL `@db.json` columns atomic. Since 0.1.72 also prunes `searchIndexes` over hidden fields, recomputes `searchable` / `vectorSearchable` / `geoSearchable`, drops unusable `search` / `index` / `vector` controls from `crud.query` / `crud.pages` (and `crud.geo`). Crud ops evaluate their handlers (`one` ← `getOne` / `getOneComposite`, `remove` ← `remove` / `removeComposite`, any allowed); actions use `useArbac`'s id (`@ArbacAction` → `@DbAction` name → …, never the method `@Id`). Since 0.1.57, fields in the caller's WRITE scopes' `allowedFields` union (or any field under an unrestricted/whitelist-free write grant) that fall OUTSIDE the read projection are STAMPED instead of pruned: they stay in `fields` as `{ writeOnly: true, filterable: false, sortable: false }` and in the serialized `type` with `db.writeOnly` metadata (subtree kept whole) — generic forms can SET sealed fields the caller can never read. Shared impl: `applyArbacMetaOverlay(meta, this.readable)` — identifiers + related tables derive from the readable (a bare identifier set, the 0.1.67 form, skips related-table identifiers). |
| `hasField(path)`                            | Every gated query position                 | Scope-aware existence (BUG-3 twin): paths outside the read-projection union answer `false` → any query reference to a hidden field gets the IDENTICAL `Unknown field "x"` 400 a nonexistent field gets (no existence/value oracle). Identifiers always pass. A `rel.x` path under a `with`-granted relation (filter / `$sort` / `$select` inside `$with=rel(...)`) is checked as `x` against the UNION of the `with.rel` sub-scopes, recursively for nested `$with`; the related table's PK / `preferredId` always pass; no `with.rel` in any role → the caller's own grant on the related table (none → the relation is unknown). Derived fields need their source visible; SQL `@db.json` columns are visible whole or not at all. Shared body: `isScopedFieldVisible(getArbacScopes() ?? [], path, this.readable)` (`getArbacScopes` = direct slot read, no `useArbac()` metadata resolution per field). Requirements: [column-scope security floor](https://aoothjs.dev/moost/db-controllers#column-scope-security-floor).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `prepareRequest(ctx)`                       | First, every endpoint                      | Resolve scopes (cached or evaluated); deny → 403. Reads: resolves the `$with` relation policy.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `onWrite(action, data)`                     | insert / replace / update                  | Nav-prop key not in any scope's `nestedWrites` → 403 `Nested writes through "x" are not allowed`. Then `applyAllowedFieldsAndSet`: path-aware whitelist (`profile.name` keeps `profile: { name }`; on PATCH only under a `@db.patch.strategy 'merge'` block — a partial replace block is dropped), dotted `set` keys set nested paths; PK / unique / version / `$cas` always kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `guardWrite(ctx)`                           | In the write's transaction                 | USING: every update/replace target's PK-exact pre-image (`ctx.current(i)`) must match the merged scope `filter` → else 404 (same as missing); all rows or nothing; duplicates count once. Then `checkRefs`: each enforced FK the write sets must reference a row the caller can read on the target → else 403 `Referenced row "x" is outside your scope`. Non-transactional adapter: WITH CHECK evaluated in memory here, before the write (unsupported op / operator or nested patch over a checked field → 403).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `guardRemove(ctx)`                          | In the delete's transaction                | USING for the deleted row (moost-db also pins the id through the remove scope's row overlay).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `checkWrite(ctx)`                           | After the write, in the txn                | WITH CHECK: `count($or(written PKs) ∧ mergedCheck) === n`, else 403 `Row outside your write scope` (rolled back). `check` defaults to `filter`; `{}` = off; unioned across roles.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `authorizeForm(name, actions)`              | `GET /meta/form/:name`                     | Served only if the caller may run ≥ 1 action taking the form (its `@ArbacAction` id, else the `@DbAction` name); else the unknown-form 404.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `actionRowScope(name)`                      | Action gate, `$actions`, `meta/actions`    | The filter of the caller's grant ON THAT ACTION (ids: every `@DbAction` method — allowed if ANY; a class-level `@DbActions` entry → controller resource + entry name; same rule in `/meta`, `authorizeForm`, the route) (custom `rowFilter` folded, attenuation conjoined); no grant → match-nothing `{ $or: [] }`. A row is actionable only if inside it — out-of-scope id → missing-row 404; `$actions` omits the action on that row. Equal filters share one object (one query). Since 0.1.72, moost-db ≥ 0.1.145.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `allowedActions(names)`                     | `$actions`, `meta/actions`                 | The row-level actions listed: those the caller holds a grant on — same rule as the `/meta` overlay (`actionArbacIds`), answered per action (memo hits) WITHOUT building the overlay. Since 0.1.72, moost-db ≥ 0.1.145.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `availableActionsById` / `availableActions` | `GET meta/actions/:id`, `meta/actions?k=v` | `{ actions, disabledReasons? }` for one row, no row data. No grant of its own: moost-db tags the handlers (`getDbEndpoint` → `"availableActions"`), and the ARBAC interceptor skips evaluating them on controllers carrying `ARBAC_DELEGATED_AUTH` (both ARBAC DB controllers — subclasses need nothing; NOT public, `isPublic` false; a plain moost-db controller stays 403); `prepareRequest` (`endpoint: "availableActions"`) serves it iff the caller holds ≥ 1 ROW-LEVEL action grant, else 403 — a read grant is NOT required and NOT enough. Request scopes = the granted row-level actions' scopes minus `filter`/`check`: row overlay unrestricted (each action's rows via `actionRowScope`), field visibility = union of the granted actions' projections (a `disabled` reason never sees a column every granted action hides). Out-of-scope ≡ unknown id → `{ actions: [] }`. Since 0.1.72.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

The read-only controller exposes only `prepareRequest`, `transformFilter`, `transformProjection`, `validateControls`, `applyMetaOverlay`, `authorizeForm`, `hasField` (same fail-closed + meta pruning + Unknown-field parity).

**Column scopes** need `@atscript/moost-db` ≥ 0.1.134 (hidden unique keys never identify a row; an excluded nested object drops its whole subtree). Since 0.1.72 (moost-db ≥ 0.1.143) they no longer depend on `arbacAuthorizeInterceptor`: unresolved scopes → `hasField` hides everything, other hooks 403 — details: [column-scope security floor](https://aoothjs.dev/moost/db-controllers#column-scope-security-floor).

## `ArbacDbScope<T>` contract

`ArbacDbScope<T = unknown>` — every field optional:

| Field            | Type                                       | Default  | Meaning                                                                                                                                                                                                                                                                                                                                                   |
| ---------------- | ------------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter?`        | `TScopeFilter`                             | —        | Row-level predicate (semantics table below).                                                                                                                                                                                                                                                                                                              |
| `projection?`    | `ProjectionOf<T>`                          | —        | Read-side field whitelist.                                                                                                                                                                                                                                                                                                                                |
| `set?`           | `Partial<Record<OwnFieldKey<T>, unknown>>` | —        | Write-side field defaults.                                                                                                                                                                                                                                                                                                                                |
| `allowedFields?` | `Array<OwnFieldKey<T>>`                    | —        | Write-side field whitelist.                                                                                                                                                                                                                                                                                                                               |
| `controls?`      | `ControlsOf<T>`                            | —        | Per-control gate map.                                                                                                                                                                                                                                                                                                                                     |
| `with?`          | `WithOf<T>`                                | —        | Per-relation sub-scope, recursive.                                                                                                                                                                                                                                                                                                                        |
| `check?`         | `TScopeFilter`                             | `filter` | WITH CHECK on written rows; `{}` = off. Enforced from 0.1.72.                                                                                                                                                                                                                                                                                             |
| `checkRefs?`     | `true \| Array<FK field \| TO relation>`   | none     | Set FKs must reference rows readable under the caller's own `query` grant on the target resource (via its registered ARBAC controller); no controller / no grant / missing row → 403. Insert/replace rows + patches touching the FK; null skipped; one `count` per FK. Enforced only if EVERY write scope enables it. Unknown name → throws. From 0.1.72. |
| `nestedWrites?`  | `Array<NavRelationKey<T>>`                 | none     | Nav relations writable through the parent payload; others 403. Parent authority. `/meta` offers only these relations as writable (a hidden one stays, stamped `db.writeOnly`). Enforced from 0.1.72.                                                                                                                                                      |

Exact shape: [docs api](https://aoothjs.dev/api/arbac-moost#arbacdbscope-t).

Pass an `.as` model as `T` (e.g. `ArbacDbScope<Task>`) to get autocomplete on `projection` / `with` / `controls` / `set` / `allowedFields` against the model's own and navigation fields. `T = unknown` (the default) keeps the legacy untyped `Record<string, ...>` shape for back-compat.

**`with[name]`** is a recursive sub-scope applied when the request expands the `name` relation via `?$with=<name>`. Policy of joined rows, at every nesting level (0.1.72+, **breaking**):

- **Declared** in any role → the union of the declared `with.<name>` sub-scopes (parent authority); roles silent on it contribute nothing.
- **Not declared** → the caller's OWN `query` grant on the related table's ARBAC resource (resource of the ARBAC DB controller serving that table): its filter / projection / controls / with apply. No such controller or no grant → `400 Unknown relation` (identical to a nonexistent relation; `Available relations:` lists only expandable ones), dropped from `/meta`. An include-mode parent projection must also name the relation.

Before 0.1.72 an undeclared relation expanded unrestricted ("silence wins") — grant `query` on related resources or declare `with.<name>` when upgrading. A field the policy hides is an unknown field in `$with` sub-queries (`$with=author(salary>1)` → 400 `Unknown field "author.salary"`) and is pruned from the `/meta` nav type.

| Field           | Used by                                    | Semantics                                                                                                                                                       |
| --------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter`        | `transformFilter`, `guardWrite/Remove`     | Row-level predicate. Merged with user filter as `$and: [scope, user]`. Union across roles = `$or` of per-role filters (existing `mergeScopeFilters` semantics). |
| `projection`    | `transformProjection`                      | Field whitelist on reads. Union across roles. Empty union → unrestricted.                                                                                       |
| `set`           | `onWrite` (via `applyAllowedFieldsAndSet`) | Field defaults overlaid on every write. Useful for tenant tagging (`{ tenantId: callerTenantId }`).                                                             |
| `allowedFields` | `onWrite` (via `applyAllowedFieldsAndSet`) | Write-side field-PATH whitelist. Union across roles. Identifier columns ALWAYS preserved (see [Identifier auto-preservation](#identifier-auto-preservation)).   |
| `controls`      | `validateControls`                         | Per-control gate map (`$with`, `$groupBy`, ...). See [Control-gate semantics](#control-gate-semantics).                                                         |

Apps can declaration-merge custom fields into `ArbacDbScope` — your scope predicate factories may produce extra keys that downstream controllers consume. Under credential attenuation each custom field needs a conjunction rule (`MoostArbac.registerScopeFields`) or the request fails with 500. A rule's `rowFilter` makes the field restrict rows on every controller path. See scopes.md rules 8 and 10.

## Control-gate semantics

`ControlGate` is `true | false | readonly string[]`. Used for query controls like `$with` and `$groupBy`.

| Gate       | Effect                                                                                                                                                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `true`     | Allowed without restriction.                                                                                                                                                                                                                                                                        |
| `false`    | Denied. Throws `HttpError(403, 'Control "$with" is not allowed for your role')`.                                                                                                                                                                                                                    |
| `string[]` | Whitelist. Rejects values not in the list. Currently supported for `$with` and `$groupBy`. `$groupBy` whitelist = SOURCE fields: a calendar-bucket alias is checked as its `$field` (whitelist `openedAt`, never the alias `week`); before 0.1.66 a bucket alias always failed the whitelist (403). |

**Cross-role union semantics**: silence wins (a more permissive role lifts denial); whitelists union additively. So if Role A says `controls.$with = false` and Role B says `controls.$with = ['comments']`, the union is `['comments']` — allowing `comments` but not other joins.

## Multi-role union

Inside the controller, `arbac.evaluate(...)` returns the array of scopes contributed by every matching role. The controller unions across roles:

- **Filters**: `$or` of per-role filters (`mergeScopeFilters`). Empty `{}` from a single role means "no constraint" — the union short-circuits to unrestricted.
- **Projections**: additive whitelist union (`unionProjections`). One unrestricted role grants unrestricted read.
- **AllowedFields**: additive whitelist union.
- **Set**: shallow merge — last-write-wins on key collision. Avoid conflicting `set` defaults across roles.
- **Controls**: per-key union with the [semantics](#control-gate-semantics) above.

## Deny verdict (match-nothing)

On a deny, `prepareRequest` answers **403** on every built-in endpoint and before every `@DbAction` handler, table-level ones included (no interceptor / `@Public()` included). Hooks reached without an entry point (a custom non-action route calling `transformFilter`) answer 403 — call `useArbacDbScope()` there. A granted action stays bound to its scope: an out-of-scope id → the missing-row 404.

## Identifier auto-preservation

`applyAllowedFieldsAndSet(data, scopes, identifierFields)` **always preserves**:

- The PK field(s) (`@meta.id`).
- Every column in any `@db.index.unique` group.
- The `@db.column.version` column and `$cas` (0.1.72+) — OCC survives any whitelist (before: a stale PATCH under a whitelist succeeded instead of 409).

This is BUG-8's fix: without auto-preservation, an `allowedFields = ['name']` scope would silently strip the PK from an `updateOne({ id, name })` patch, causing the write to fail or — worse — produce a multi-row update.

The preserved list is computed from the table's `identifications` + `versionColumn`, memoized per controller class.

## Wiring example

```ts
import { ArbacResource, AsArbacDbController } from "@aooth/arbac-moost";
import { TableController } from "@atscript/moost-db";
import type { AtscriptDbTable } from "@atscript/db";
import { Article } from "./article.as";

export function makeArticlesController(table: AtscriptDbTable<typeof Article>) {
  @TableController(table)
  @ArbacResource("articles")
  class ArticlesController extends AsArbacDbController<typeof Article> {}
  return ArticlesController;
}
```

The table is bound through `@TableController(table)` from `@atscript/moost-db`. The subclass has a default (no-arg) constructor — **never** `super({ table, model })` or `super(table, Article)`.

With a role like:

```ts
import { allowTableRead, defineRole } from "@aooth/arbac";
import type { ArbacDbScope } from "@aooth/arbac-moost";
import { Article } from "./article.as";

type UserAttrs = { tenantId: string; id: string };

defineRole<UserAttrs>()
  .id("editor")
  .use(
    allowTableRead<UserAttrs, ArbacDbScope<typeof Article>>("articles", {
      scope: (attrs) => ({
        filter: { tenantId: attrs.tenantId },
        projection: { title: 1, body: 1, tenantId: 1, id: 1 },
        set: { tenantId: attrs.tenantId },
        allowedFields: ["title", "body"],
        controls: { $with: ["comments"], $groupBy: false },
      }),
    }),
  )
  .build();
```

Note: pass typed scopes **per-privilege** via the `ArbacDbScope<Article>` generic on `allowTable*` — don't pin a single `ArbacDbScope<X>` at the `defineRole<UserAttrs, ArbacDbScope<X>>()` level, because `ArbacDbScope<T>` is not assignable to `ArbacDbScope<unknown>` across `allowTable*` calls for different models.

A `GET /articles?$with=comments` request from an `editor`:

1. `transformFilter`: user filter merged with `{ tenantId: user.attrs.tenantId }` as `$and`.
2. `transformProjection`: response restricted to `{ title, body, tenantId, id }`.
3. `validateControls`: `$with: ['comments']` allowed; `$with: ['author']` → 403.

For read/write/action scopes of one table sharing a row filter, use `defineTableAccess` ([builder.md](./builder.md)) instead of separate `allowTable*` calls.

A `PUT /articles/42` with `{ id: 42, title: 'x', body: 'y', tenantId: 'other-tenant' }` from a role holding a write grant with the same scope:

1. `prepareRequest`: the write grant is resolved (none → 403, `@Public()` does not bypass).
2. `onWrite`: a nav-prop key not in `nestedWrites` → 403; `applyAllowedFieldsAndSet` strips fields outside `allowedFields = ['title', 'body']`, preserves `id`, overlays `set = { tenantId: user.attrs.tenantId }` — the malicious `tenantId` is overwritten.
3. `guardWrite` (USING): the stored row 42, read by exact PK inside the transaction, must match `{ tenantId }` → else 404 (same as a missing row).
4. `checkWrite` (WITH CHECK): the written row must match `check` (default `filter`) → else 403 and the write rolls back.

## Custom routes: `useArbacDbScope()`

`@DbAction` handlers / custom routes that query `this.table` directly skip the controller hooks — apply the scope with `useArbacDbScope()` (`import { useArbacDbScope } from "@aooth/arbac-moost"`):

```ts
const scope = await useArbacDbScope<typeof Task>();
await this.table.updateMany(scope.filter({ id }), { status: "done", ...scope.set() });
await scope.assertRowsInScope(this.table, ids); // before id-addressed writes that don't filter by scope
await this.table.insertOne({ ...row, ...scope.set() }, scope.writeOptions(this.table)); // CRUD write enforcement
await this.table.deleteOne(id, scope.removeOptions(this.table)); // out-of-scope → 404
```

| #   | Rule                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `filter(extra?)` = scope-filter union `$and` `extra`. NEVER `{ ...scopeFilter, ...extra }` — a same-key extra replaces the scope and widens access.                                                                                                                                                                                                                                                                 |
| 2   | `set()` = merged `set` overrides; spread LAST over your data. `check()` = effective WITH CHECK (`check` ?? `filter`, unioned). `{}` = unrestricted for both filters.                                                                                                                                                                                                                                                |
| 3   | `assertRowsInScope(table, ids)`: each id pinned to exactly ONE row (PK first, else a scope-visible unique key), deduped, one `count`; any missing or out-of-scope id → 404 `Not found`.                                                                                                                                                                                                                             |
| 4   | Async + fail-closed: no cached scopes (public route, no interceptor) → evaluates the route's resource/action; deny (incl. the empty-scope rule) → 403.                                                                                                                                                                                                                                                              |
| 5   | Handler-side writes skip the controller guards → pass `scope.writeOptions(this.table)` (insert/replace/update: nested writes 403, USING 404, `checkRefs` 403, WITH CHECK 403 rolled back) / `scope.removeOptions(this.table)` (delete). NOT applied: `allowedFields` / `set` — spread `scope.set()` yourself. Grant `checkRefs` on the ACTION scope too. `assertRefsInScope(table, rows)` = standalone `checkRefs`. |
| 6   | `checkRefs` FK values: class instances (Mongo `ObjectId`, `Date`) are values; a plain object / array (operator shape) → 403.                                                                                                                                                                                                                                                                                        |

## Custom ARBAC controllers (other moost-db bases)

Compose the hook bodies instead of re-implementing them (all since 0.1.72, `import { … } from "@aooth/arbac-moost"`); signatures: [docs api](https://aoothjs.dev/api/arbac-moost#custom-arbac-controller-building-blocks).

| Hook / need                                 | Use                                                                                                                                                                                                         |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prepareRequest(ctx)`                       | `prepareArbacRequest(ctx, this.readable)` — resolve scopes (403 on deny), `$with` policy on reads                                                                                                           |
| `transformFilter(filter)` (sync)            | `arbacRowFilter(filter)`                                                                                                                                                                                    |
| `transformProjection(p)` (sync)             | `applyArbacProjection(p, requireRequestScopes(), this.readable)`                                                                                                                                            |
| `validateControls(c)` (sync)                | `applyArbacControls(c, requireRequestScopes())` + `applyArbacRelationScopes(c, scopes, this.readable)`                                                                                                      |
| `hasField(path)` (sync)                     | `super.hasField(path) && requestFieldVisible(path, this.readable)` — unresolved = hide everything                                                                                                           |
| `guardWrite` / `checkWrite` / `guardRemove` | `guardArbacWrite(ctx, requireRequestScopes(), table, this.readable)` / `checkArbacWrite(ctx, scopes)` / `guardArbacRemove(ctx, scopes, table)`                                                              |
| `authorizeForm(name, actions)`              | `authorizeArbacForm(actions)`                                                                                                                                                                               |
| `actionRowScope(name)`                      | `arbacActionRowScope(name)` — the action's own grant filter (moost-db ≥ 0.1.145)                                                                                                                            |
| `GET meta/actions/:id` route                | `prepareArbacRequest` authorizes `endpoint: "availableActions"`; ALSO add `[ARBAC_DELEGATED_AUTH](m) { return getDbEndpoint(this, m) !== undefined }` so the interceptor delegates — else it 403s the route |
| `allowedActions(names)`                     | `arbacAllowedActions(names)` — per-action grants (the `/meta` overlay's rule) without building the overlay                                                                                                  |
| `@DbAction` handlers                        | nothing extra — `prepareArbacRequest` runs for `endpoint: "action"` too; never read action ids / rows inside `prepareRequest` (the slot would wait on itself)                                               |
| Be a `$with` target for other controllers   | field initializer `registerArbacDbTarget(this)` — else undeclared relations to its table are unknown                                                                                                        |
| The ids a handler is authorized as          | `resolveHandlerArbacIds(instance, methodName)` (`useArbac()` precedence)                                                                                                                                    |

Resolve scopes only at the entry point (`resolveRequestScopes`, inside `prepareArbacRequest`); never treat unresolved scopes as unrestricted. `ensureRequestScopes` / `resolveRelationScopes` / exported `enforcedRefs` + `assertRefsInScope` / `arbacDbActionGuard` + `WithArbacDbActionGuard` were 0.1.72 pre-release names — gone. Hidden `$with` relations: skipped by the overlay, moost-db answers `Unknown relation` via `hasField` at every level.

## Value-help controllers

`AsArbacJsonValueHelpController<T>` (static rows) / `AsArbacValueHelpController<T>` (abstract; implement `query` + `getOne`) — ARBAC mirrors of moost-db's value-help controllers (`/query`, `/pages`, `/one`, `/meta`). Since 0.1.72; needs `@atscript/moost-db` ≥ 0.1.143. `import { AsArbacJsonValueHelpController, AsArbacValueHelpController } from "@aooth/arbac-moost"`.

```ts
@Controller("dicts/status")
@ArbacResource("dict-status")
class StatusDict extends AsArbacJsonValueHelpController<typeof Status> {
  constructor(app: Moost) {
    super(Status, ROWS, app);
  }
}
// grant: allowTableRead("dict-status", { scope: () => ({ filter: { active: true }, projection: { internal: 0 } }) })
```

| #   | Rule                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Action ids = table READ ids: `runQuery`→`query`, `runPages`→`pages`, `runGetOne`→`getOne`, `runGetOneComposite`→`getOneComposite`, `meta`. Grant with `allowTableRead` / `allowTableOps(r, ["read"])`. |
| 2   | Resource = `@ArbacResource(...)` (else controller id, then class name).                                                                                                                                |
| 3   | Plain moost-db `AsJsonValueHelpController` under ARBAC: action ids are the method names (`runQuery`…) and NO scope applies — use the ARBAC class for anything scoped.                                  |
| 4   | Every route resolves scopes first (cached by the interceptor, else evaluated). Deny → 403 on all routes incl. `/meta`. No interceptor ≠ open. `@Public()` / `arbacPublic` does NOT bypass.             |
| 5   | `filter` → `$and` with the request filter; `/one` outside it → 404. `projection` → hidden columns stripped, PK always returned unless an explicit `$select` omits it.                                  |
| 6   | Hidden field in filter / `$sort` / `$select` → `400 Unknown field "x"`; never matched by `$search`. `controls` gates (e.g. `$search: false`) → 403.                                                    |
| 7   | `/meta`: `crud` filtered per action, `fields` / `type` pruned, `searchable: false` when no searchable field stays visible.                                                                             |
| 8   | `with` / `set` / `allowedFields` / `check` / `nestedWrites` do not apply (read-only, no relations).                                                                                                    |
| 9   | Custom `query` (abstract class): `filter` and `$select` arrive scoped; implement `$search` over fields `this.hasField(f)` accepts.                                                                     |
| 10  | Overriding `runQuery`/`runPages`/`runGetOne`/`runGetOneComposite` → re-apply `@ArbacAction(...)`; overriding any hook → keep the `super` call.                                                         |
