# Rate limiting

Core: `RateLimiter` (`@aooth/auth`) — fixed window, window-aligned keys, `check()` counts / `peek()` reads. Moost: `@RateLimit(...)` metadata + `rateLimitInterceptors()` PAIR enforcing it (429 + `RateLimit-*` headers).

## Quick start

```ts
import { RateLimiter } from "@aooth/auth";
import { RateLimitStoreRedis } from "@aooth/auth/redis";
import { authGuardInterceptor, Public, RateLimit, rateLimitInterceptors } from "@aooth/auth-moost";

const limiter = new RateLimiter({ store: new RateLimitStoreRedis({ redis }) });
app.applyGlobalInterceptors(authGuardInterceptor(), ...rateLimitInterceptors({ limiter })); // SPREAD

@Controller("api")
class Api {
  @Public()
  @RateLimit("20/1m") // policy 1: per IP
  @RateLimit("5/15m", { key: perAccountKey, id: "acct" }) // policy 2: independent bucket
  @Post("login")
  login() {}
}
```

## Invariants

| #   | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Register the PAIR with a spread.** `BEFORE_GUARD` phase owns `'ip'` / function-keyed policies; `AFTER_GUARD` owns named subjects (`'user'`, `'session'`, `'auto'`, app kinds via `setRateLimitSubject`). Dropping one silently disables its policies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 2   | **Stacked `@RateLimit` decorators = INDEPENDENT policies** (own key + bucket; all must pass) — since 0.2. Several rules in ONE decorator share one key + bucket. Buckets: `<Class>.<method>`, `…#1`, `…#2` unless `id` given — positional, so reordering decorators moves counters: give every stacked policy an explicit `id`. Method-level policies replace class-level — see #15.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 3   | **Metadata shape (since 0.2):** `TRateLimitMeta.rateLimitPolicies: { rules, options? }[]` (one entry per `@RateLimit`). Only matters to code reading the mate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 4   | **Key function** runs PRE-guard (no `useAuth()` / subjects). May return a composite subject (`ip                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | user:<submitted name>`) or `null`/`undefined`to SKIP the policy (nothing counted) — e.g. count only submissions carrying a password. All policies skipped →`useRateLimit().decision === null`, no headers. |
| 5   | **Decision across policies:** the rejecting one (frees capacity last), else least remaining. `RateLimit-Limit/Remaining/Reset` from it; `RateLimit-Policy` lists every evaluated policy. `useRateLimit().decision` = that governing decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 6   | **Client IP = the HTTP app's `useRequest().getIp()`** — one source for `'ip'` buckets, one-time-code failure budgets, session/device-trust IPs. Behind a proxy set `trustProxy` (address list / CIDR preferred over hop count; `{ addresses, hops }` caps both when clients can sit inside the trusted range, wooks 0.8.3+) + `proxyHeaders` (`'x-forwarded'` \| `'forwarded'`) on `createHttpApp(...)`. `rateLimitInterceptors({ trustProxy })` is DEPRECATED since 0.2.7 (one-time `console.warn`, removed in 0.3) — still honoured: `true` = one hop, any address, read from the app's `proxyHeaders` family, and it then feeds all those IPs. Never write it in new code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 7   | **`limiter.peek(scope, subject, rules)`** = same decision, nothing spent (`remaining` left, `allowed` = would a check pass). Needs `store.get()` — `RateLimitStoreMemory` / `RateLimitStoreRedis` have it (since 0.2); custom store without it → throws. Stores may implement optional `expire(key, ttlMs)` (sliding TTL); `RateLimitStoreMemory({ maxEntries })` caps counters (oldest dropped).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 8   | **Not for calendar quotas.** Windows are fixed durations aligned to the Unix epoch — a "N per calendar day/month in the user's timezone" allowance is a DB ledger, not `@RateLimit`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 9   | **Not account lockout.** `UserService` lockout counts failed credentials per account; limits count requests per caller. Use both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 10  | **Multi-instance → `RateLimitStoreRedis`.** The default memory limiter is per process AND per `rateLimitInterceptors()` call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 11  | **Testing:** pass your own `new RateLimiter({ store })` (memory store you hold) to `rateLimitInterceptors`, call `store.clear()` between tests; inject `clock` into the limiter for window stepping.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 12  | `@RateLimit(...)` is enforced only when the interceptors are installed — this includes the **bundled limits**: `POST /auth/refresh` → `aooth.refresh` `150/5m` per IP (pre-guard: junk-token floods cost no lookups) + `aooth.refresh-token` `10/1m` per presented refresh token from any IP; `GET /auth/invite/post-redemption` → `aooth.invite-post-redemption` `30/5m` per IP; auth workflow anonymous sends (recovery code / magic link / signup code requests, real or not) → `aooth.send` `20/15m` per IP, enforced inside the workflow via the installed interceptors' limiter (429 ends the run); code sends after a first factor (email/SMS 2FA, enrolment, channel check, federated link proof) → `aooth.send-user` `10/1h` per ACCOUNT (`user:<id>`, anti SMS-pumping); `POST /auth/token` → `aooth.token` `150/5m` per IP + `aooth.token-refresh` `10/1m` per presented `refresh_token` (refresh grant only, hashed); `POST /auth/register` → `aooth.register` `20/1h` per IP. Route policies are pre-guard; every 429 is the coded moost body, not OAuth `{error}`. Re-tune/disable by policy id with `rateLimitInterceptors({ policies: { "aooth.refresh": "600/5m", "aooth.refresh-token": false } })` (DECLARED ids only — bundled + every `@RateLimit({ id })`; an unknown id THROWS at configuration; declare (import controllers) before configuring; rules replace, key + id kept; empty list throws) — don't subclass the controller for it. |
| 14  | **`'refresh-token'` key** (built-in named subject, post-guard): the token the request presents (body `refreshToken`, else the refresh cookie), base64url-canonicalized then SHA-256-hashed (`rt:<22 chars>`; lenient spellings `=`/whitespace/`+/`/stray chars share one bucket) — never the raw secret in store keys. No token → the policy is SKIPPED (no IP fallback, unlike other named kinds). Keyed on the token, not the session: the session is only known after the lookup the limit guards.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 13  | **429 body = `{ statusCode, message, code: "RATE_LIMITED", params: { policy, limit, window, retryAfter } }`** — `policy` = the policy `id` (default `<Class>.<method>`/`#n`; set `id` for a stable public name), `window` + `retryAfter` in SECONDS (`retryAfter` = `Retry-After`). `message` is English (`RATE_LIMIT_MESSAGES.RATE_LIMITED` = `"Too many requests. Retry after {retryAfter} s."` since 0.2.5; rule messages may use `{{limit}}`/`{{window}}`/`{{delta}}` humanized or `{limit}`/`{window}`/`{retryAfter}` seconds); to localize, translate by `code` + `params` (moost translator via `MoostHttp`, a client, or the HTTP app's error-body hook — a translation replaces a rule's own English message) — never parse `message`. Same `code`/`params` on `RateLimitDecision` when `!allowed`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 15  | **Which policies govern a route — first that exists, never combined:** (1) method-level `@RateLimit`s, INCLUDING ones inherited from a base class (every bundled `aooth.*` route), (2) class-level `@RateLimit`, (3) interceptor `rules`. ⇒ a class-level `@RateLimit` on a subclass of `AuthController` / `AuthorizeController` NEVER covers the bundled routes. Re-tune those with `rateLimitInterceptors({ policies: { "aooth.token": "…" } })`, or override the handler with its own method-level `@RateLimit`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 16  | **Each policy is checked ONCE per event PER LIMITER** (since 0.2.7), whoever registered the pair (global + `@RateLimited`, or two apps sharing one router where wooks runs the next app's chain after a handler throws). Same limiter, policy already checked → not counted again; if it rejected, the later chain re-answers the same 429. A policy the later chain adds is checked on its own. Another limiter (each `rateLimitInterceptors()` call makes its own unless `limiter` is passed) counts its own hit, even for the same scope id; one SHARED limiter checks a scope id once per event, under the first chain's rules (its `policies` overrides). A route with no policy / `@RateLimit(false)` is never handed another app's 429.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
