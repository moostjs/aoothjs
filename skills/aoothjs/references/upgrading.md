# upgrading

Load when bumping `@aooth/*`, when an app "worked before" an upgrade, or when writing code against an older aooth. All `@aooth/*` packages share one version — bump them together, with the matching ecosystem line ([ecosystem.md](./ecosystem.md) § Peer dependencies).

## 0.2.7 — limiter `trustProxy` deprecated; `@WfTrigger` override replaces; SQL null reads

- **`rateLimitInterceptors({ trustProxy })` deprecated** (one-time warning, removed in 0.3). `true` still = one hop, now read from the app's `proxyHeaders` family (spoofed `X-Forwarded-For` under `'forwarded'` no longer picks a bucket); it feeds every aooth client IP while set. Move `trustProxy` (+ `proxyHeaders`) to `createHttpApp(...)` before 0.3 — with neither, every caller behind the proxy shares one budget. [rate-limit.md](./rate-limit.md) #6.
- **Re-decorating an inherited trigger handler with `@WfTrigger({...})` REPLACES the base options** (the override's `allow` is the only list; hooks too) and the trigger runs ONCE per request (before: base trigger also ran — a second `handle()` when the reply was `undefined`). Override without its own `@WfTrigger` → base options kept. [controllers.md](./controllers.md).
- SQL stores: unset optional columns no longer leak as `null` from the bundled atscript-db user / federated-identity / credential stores → pre-0.2 pending invites (NULL `inviteNonce`) accept again (were `410 INVITE_REPLACED`); refresh-token reuse on a legacy row without `sessionId` revokes all the user's sessions (was skipped). No app change.
- New: `peekInvite(token, { trigger, users })`, `WfTriggerProvider.peek(token)` ([invites.md](./invites.md)); `?kind=a,b` comma list on `SessionsController` reads ([sessions.md](./sessions.md)); bare `@aooth/user/atscript-db/model` (+ `federated-model`) subpath.

## 0.2.6 — namespaced message codes; magic links; token-endpoint rate limits

- **Renamed codes** (one global registry, last catalogue wins a code's template → generic names now prefixed). Update translator catalogues, `AuthWorkflowOpts.messages`, clients/tests branching on body `code`:
  - `AOOTH_MESSAGES` → `AOOTH_` + `ACCOUNT_LOCKED`, `INVALID_CODE`, `CODE_EXPIRED`, `TOO_MANY_CODE_ATTEMPTS`, `RESEND_WAIT`, `RESEND_WAIT_ANOTHER`, `RESEND_WAIT_CHANNEL`, `ADDRESS_REQUIRED`, `INVALID_EMAIL_ADDRESS`, `INVALID_PHONE_NUMBER`, `UNKNOWN_METHOD`, `METHOD_UNAVAILABLE`, `METHOD_NOT_CHANGEABLE`, `CHOOSE_OPTION`, `ACCOUNT_LINKED`, `ACCOUNT_CREATED`, `ALREADY_HAVE_ACCOUNT`, `INVALID_ROLE`, `USER_ALREADY_EXISTS` (409 body code too), `BACK`, `GO_NOW`.
  - `AOOTH_HTTP_MESSAGES` → `AOOTH_` + `AUTH_REQUIRED`, `CREDENTIAL_INVALID`, `NOT_AUTHENTICATED`, `MISSING_UID`, `UNKNOWN_PROVIDER`, `WORKFLOW_NOT_ALLOWED`.
  - `ARBAC_MESSAGES` → `ARBAC_` + `INSUFFICIENT_PRIVILEGES`, `CONTROL_NOT_ALLOWED`, `CONTROL_VALUE_NOT_ALLOWED`, `NESTED_WRITE_NOT_ALLOWED`, `ROW_OUT_OF_SCOPE`, `REFERENCE_OUT_OF_SCOPE`, `INVALID_QUERY_STRING`.
  - `UserAuthError`: `type` unchanged (branch on it); new `err.code` = message code (`USER_AUTH_ERROR_CODES`): `ALREADY_EXISTS`/`LOCKED`/`INACTIVE`/`POLICY_VIOLATION`/`CAS_EXHAUSTED` → `AOOTH_USER_<type>`; `USER_AUTH_ERROR_MESSAGES` keyed by code; `userAuthErrorToHttp()` body `code` = `err.code`.
  - Kept (shared on purpose): `NOT_FOUND` (text now neutral "Not found", was "User not found" — also the error's default message), `INVALID_CREDENTIALS`, `RATE_LIMITED`.
- **`POST /auth/refresh` rate limited** (when `rateLimitInterceptors` are installed): `aooth.refresh` `150/5m` per IP + `aooth.refresh-token` `10/1m` per presented refresh token → coded 429. Re-tune/disable: `rateLimitInterceptors({ policies: { "aooth.refresh": "300/5m" } })` ([rate-limit.md](./rate-limit.md)).
- **Magic links** (opt-in): recovery `resolveRecoveryDeliveryMode` → `'magicLink'`/`'choice'`; login `resolveAlternateCredentials().magicLink` (was 501). New email kind `login.magicLink`; `WfTriggerProvider` gains the `magic-link` outlet + state strategy (keep them when replacing `outlets` / `stateRegistry()`), `magicLinkStore()` seam. `magicLinkSkipsMfa` removed (link = first factor only). [workflows.md](./workflows.md).
- `/auth/token` (`aooth.token` 150/5m/IP, `aooth.token-refresh` 10/1m/refresh_token) and `/auth/register` (`aooth.register` 20/1h/IP) rate limited.
- ARBAC: an un-aliased inner aggregate of a `$from` (e.g. `count(*)` → `count_star`) is an inner column for the outer `$groupBy` whitelist check (was 403).
- **Recovery anti-enumeration**: unknown / inactive / M2-undeliverable identifiers now get the SAME code form (nothing sent, no code accepted) instead of a generic finish; inactive accounts get no code; M2 code form shows no destination; consents staged after code verification; `RECOVERY_INSTRUCTIONS_SENT` removed. `embedRecovery` removed from the alt-credentials policy (unused).
- Magic links: opening shows `MagicLinkConfirmForm` (used up on submit — scanners don't spend it); opt-in `magicLinkSameBrowser` cookie binding; `Referrer-Policy: no-referrer` on the landing page.
- Recovery: `ctx.subject` unset for EVERY run until the code is verified (account resolved from `ctx.email` on send/check; no `recoveryGhost` field).
- `policies` keys = DECLARED ids only (throws otherwise); post-redemption policy id `aooth.invite-post-redemption` (was `AuthController.invitePostRedemption`); new `aooth.send` 20/15m per IP on anonymous sends (429 ends the run).
- Workflow states tagged with their strategy (cross-strategy resume → 410); encapsulated tokens padded to 256 B (longer); overriding `stateRegistry()` drops both. `CredentialStoreEncapsulated` rejects non-canonical base64url token spellings.
- `RecoveryFactorForm` removed (never rendered by any step).
- Peers `@atscript/db` / `moost-db` `^0.1.174`, `@atscript/typescript` `^0.2.9`, `@atscript/moost-wf` `^0.1.169` (+ atscript-ui clients `^0.1.169`). ARBAC 404s (USING, delete, `assertRowsInScope`) = moost-db `notFoundError()` body `{ statusCode, message: "Not found", code: "NOT_FOUND", error }` — identical for missing and out-of-scope; action-identifier miss uses it too (was "Row not found for action identifier").
- **One-time codes server-side** (every emailed/texted code): attempt limit counted in `lockoutShadowStore` (SHARE it across instances), past the limit every submit = `AOOTH_TOO_MANY_CODE_ATTEMPTS` (was `AOOTH_CODE_EXPIRED` after the first), verified code single-use; `ctx.pin`/`ctx.pinAttempts` gone → `ctx.pinNonce` + `ctx.pinDigest` (codes in flight at upgrade expire); new `WfTriggerProvider.pincodeSecret()` (default wf-state secret) / `AuthWorkflow.pincodeKey()`; recovery code bound to the account + address resolved at send; `resolvePincodeTarget` also runs for unknown/inactive recovery identifiers (placeholder subject; errors discarded). Server-side resend wait per (destination, client IP) (typed identifier for recovery/signup; new run in the wait sends nothing) + `mfa.pincodeMaxSendsGlobal` 10 sends per destination from all IPs per window; failure budgets `mfa.pincodeMaxFailures` 10 per client IP + `pincodeMaxFailuresGlobal` 100 per destination / `pincodeFailureWindowMs` 1h → `429 AOOTH_CODE_LIMIT_REACHED` (behind a proxy: `trustProxy` on the HTTP app — the limiter option is deprecated since 0.2.7); new policy `aooth.send-user` 10/1h per account; subclass overrides: `mintPin(ctx, binding, length?, ttlMs?)`, `await verifyPin(ctx, code, binding, target)`, custom send = `if (await claimCodeSend(target, account?))` send.
- New `auto-login-check` step before `record-login` (invite/recovery/signup auto-login): inactive account → no `lastLogin`, no `afterLogin`, no session; `finalize-auto-login` keeps its own 403 guard. Login: new `check-can-sign-in` step (deactivated/locked while paused → error finish, no stamp/session); `issue` + `mint-authz-code` re-check `assertCanSignIn`.
- Recommended: `HandleStateStrategy({ store, hashHandles: true })` for `storeStrategy()` (old UUID handles still resolve); durable `magicLinkStore()` in production.

## 0.2.5 — localization through the moost translator; `$from` gates

Peers: `moost` / `@moostjs/*` `^0.7.3` (translator API), `@wooksjs/*` `^0.8.1`, `@atscript/typescript` `^0.2.8`, `@atscript/moost-wf` `^0.1.167`, `@atscript/db` + `moost-db` `^0.1.171`. SPA rendering the bundled forms: `@atscript/ui-fns` / `vue-form` / `vue-wf` `^0.1.167` (forms' expressions call the `t` arg) — **clients < 0.1.165 can't render the workflow forms (no `t`) — upgrade client and server together.** Apps compiling the forms themselves (`extends`, `.as` source) need `@atscript/ui-fns` ≥ 0.1.166 in the atscript config, else paragraph (`fn.value`) texts stay English. No action needed until the app calls moost `setTranslator`; then:

- Workflow texts: `messages` → translator (request locale) → English. Every 4xx `HttpError` has `code` + `params` (new `AOOTH_HTTP_MESSAGES`, `ARBAC_MESSAGES`); `MoostHttp` translates error bodies by code → `message` may be localized: branch on `code`.
- Password policies carry `PP_*` codes; `PolicyCheckResult.policies[]` / `POLICY_VIOLATION` `params.policies[]` gain `errorMessage?`, `code?`, `params?`.
- New workflow codes (English unchanged): `SET_PASSWORD_*_{HEADING,INTRO}`, `CHANGE_PASSWORD_{HEADING,INTRO}`, `ACCOUNT_CREATED`, `UNKNOWN_SSO_PROVIDER`, `TOTP_NOT_CONFIGURED`, `CODE_EXPIRED`, `TOO_MANY_CODE_ATTEMPTS`, `ADDRESS_REQUIRED`, `INVALID_EMAIL_ADDRESS`, `INVALID_PHONE_NUMBER`, `OTP_DISCLOSURE_{EMAIL,PHONE}`, `LAST_MFA_METHOD_NOT_REMOVABLE`, `MFA_METHOD_*`.
- **Hook change:** `resolveSetPasswordCopy()` default returns codes (`{ headingCode, introCode }`, type `SetPasswordCopy`), not text; returned `heading`/`intro` text wins and is shown as is. `resolveAccept()` default has no `confirmationMessage` (rendered from `ACCOUNT_CREATED`). State never holds translations: `WfTriggerProvider` strips the rendered `ctx.public` projection in `beforePersist` (an app's own `beforePersist` still runs, after the strip).
- Rate limiter: default 429 text `RATE_LIMIT_MESSAGES.RATE_LIMITED` = `"Too many requests. Retry after {retryAfter} s."` (was "Please try again in {{delta}}", humanized); rule messages accept `{limit}`/`{window}`/`{retryAfter}`; under a translator a rule's English `message` is replaced by the `RATE_LIMITED` translation.
- `AuthEmailEvent` / `AuthSmsEvent` / `AuthDeliveryPayload` gain `locale?` — copy it when mapping `deliver()` payloads.
- Bundled forms served translated (labels by text, validator messages by code, expression texts via `t`, served per form in `$i18n`); client sends the locale with `provideAsLocale`. English unchanged. New export `USER_AUTH_ERROR_MESSAGES` (`@aooth/user`, code = type), registered by auth-moost.
- ARBAC: `controls.$from` boolean gate (403 `CONTROL_NOT_ALLOWED`); outer `$groupBy` on inner columns passes a `$groupBy` whitelist (was 403); `/meta` prunes `nestedAggregates` / `from` / `conditionalAggregates` / `distinctFieldLists` with the gates.

See [messages.md](./messages.md), [db-controllers.md](./db-controllers.md).

## 0.2.4 — insert read-back; reads under write handlers 403

**Breaking:** on an ARBAC DB controller, a read (`this.getOne/getOneComposite/query/pages/geo`) inside an `insert` / `update` / `replace` / `remove` / `removeComposite` override → **403** (it used to run under the WRITE grant; the 403 comes after the committed write). Migration: `await super.update(payload); return readBackUnderReadGrant(id, () => this.getOne(String(id), ""))` — the read grant on the `/one` handler; `undefined` when not allowed.

Additive: `returnRepresentation()` → `true` on an `AsArbacDbController` subclass: `POST /` + `Prefer: return=representation` answers `row` = what `GET /one/:id` answers the caller (READ grant, not the insert grant). Default off. See [db-controllers.md](./db-controllers.md) § Protected hook table.

## 0.2.3 — moost 0.7.2 line; additive features

Peers: `moost` / `@moostjs/*` `^0.7.2`, `@atscript/typescript` `^0.2.4`, `@atscript/moost-wf` `^0.1.164`, `@atscript/db` + `moost-db` `^0.1.168`. moost 0.7.2 accumulates class-level interceptors, pipes and auth transports along `extends` under `@Inherit()` — a subclass of an aooth controller keeps the base's guards and error mapping.

Additive: `WfTriggerProvider.triggerHooks()` / `@WfTrigger({ around, beforePersist, renderEnvelope, restoreOnError, maxRestores })` (see [workflows.md](./workflows.md)); coded 429 `code: "RATE_LIMITED"` with `params` `limit` / `window` / `retryAfter` (seconds) (see [rate-limit.md](./rate-limit.md)); `userAuthErrorToHttp()` / `userAuthErrorInterceptor` map `UserAuthError` → coded 4xx `HttpError`; `UserService.revokeInvitation(id)` (invite link then 410, see [invites.md](./invites.md)); `useArbac().principal()` → user id, effective roles, attrs.

## 0.2.2 — dependency update
